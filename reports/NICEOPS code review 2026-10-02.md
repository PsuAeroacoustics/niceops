## 1. Summary

**The numerical core is in good shape; the defects are at its edges.** Baseline and HEAD both pass their full CTest suites (53, then 65 tests), the demo output is byte-identical to `golden/197421_LAE.csv`, an asserts-on build passes all 65 tests, and the hot loop sits at its documented cost. No reviewer found an arithmetic error in the broadband propagation chain; the nearest thing is the unbounded inward spreading extrapolation inside the 30 m sphere, which moves 28 demo cells by up to 4.4 dB (section 4). The dedicated end-to-end physics-chain sweep did not run, so read that as absence of evidence, not a clean bill.

What the review did find clusters in four places:

1. **Bad input produces a plausible-looking wrong result, exit 0, nothing on screen.** A flat or descending time column gives an all `-inf` or all `nan` footprint; one NaN in one coordinate of a 6551-row track turns 298 of 483 cells to NaN; a unit slip on `--temperature`, `--pressure` or `--humidity` shifts the footprint 4 to 10 dB; a geodetic track with no clock gets +10 dB DNL. Failures that are caught are written only to `log/niceops.log`, so the terminal stays empty.
2. **Multi-trajectory and threaded plumbing.** With several `-t`, `-i` and `--band_history` overwrite each other. At the default thread count any exception inside the observer loop calls `std::terminate`, which defeats the per-trajectory error handling the code documents.
3. **One documented invariant is false.** `DirectionBounds` is not an upper bound within about 1 degree of the nose axis (it is exceeded by up to 0.7 dB), and the unit test that guards it never samples there. No output difference has been found, so it is latent, but "the windowed path is exact" rests on it.
4. **The docs describe a program that no longer exists.** CLAUDE.md and the README still describe the first-crossing SEL window, `expand_window()`, "70 percent evaluated, 1.2x faster", and a spectral path that is opt-in and unwindowed. The code has used the outermost-crossing window since `9d6e986`, evaluates 93.9 percent of pairs on the demo, and on broadband runs the windowed path now costs about 5 percent *more* CPU than marching every state.

The test harness has a hole under all of it: `golden_compare` accepts NaN or infinity against anything (R), so every golden and every "windowed is exact" test would pass on corrupt output.

Performance: nothing found changes the cost model. The candidates the reviewers measured are worth a few percent each (section 5). The two with real weight are refraction-table build time (about 3 CPU-s per distinct microphone height per run) and database load (about 0.1 s of 1.0 s).

**Second pass (section 10).** The physics chain was re-implemented independently and agrees with `niceops` to 5.7e-14 dB (geometry to level), 2.8e-14 dB (SEL) and 1.3e-3 dB (spectral path), so the arithmetic is right; what the reviewers found is about inputs and defaults. A vehicle JSON that disagrees with the database in weight, density or radius is never compared (only tip speed, in one log line): a 10 percent weight error moves the footprint 0.75 dB median and a 4.6 percent tip-speed error 1.13 dB, silently. The spectral path defaults humidity to 20 percent and derives pressure from density without saying so, worth 1.2 to 3.0 dB median depending on what the vehicle file omits. In the stratified code the 32-sample arrival search is not converged for low sources in a duct (4.3 percent of pairs more than 1 dB from a 2048-sample reference; up to 10.5 dB in single cells of a low-source footprint), a NaN can escape at a shadow boundary, and the arrival summation is untested; but the peak-search bound for sums of arrivals held in about 6e7 checks, and the windowed table runs matched marched output in 24 combinations. The one-line PE band-average fix is now measured: 0.16 to 0.47 dB rms downwind against 0.015 to 0.04.

## 3. Correctness and robustness: the rest

**Reproduced on HEAD (R) or verified twice (V2)**

- **`--trim` past the lowest or slowest point** (`trajectory.cpp:795`, no `ixmin <= ixmax` check). R: `--trim 333` and `340` (the end point is at 330.9 ft) exit 1 with "Skipping ...: vector"; `--trim 331` exits 0 with a one-state trajectory. V2, C x4. Fix: check and `input_error` with a diagnosis; add the missing `watts_trim` test.
- **`niceops_pe_field --source_height 0` without `--top` hangs.** R: killed by the 30 s alarm with no output; the same command with a source at 100 ft and `--top 200` finishes at once. Research tool; low priority.
- **`--db_cutoff` exactness is documented wrongly** (`README.md:235`, "every cell at or above 85 dB is unchanged to the last bit"). V2: on the demo 157 of 592 cells at or above 85 dB change, worst 0.43 dB, because the cull works on instantaneous level while cells are SELs (SEL exceeds peak by 1 to 12 dB). The code's own promise (exact for any observer whose *peak* reaches the cutoff) holds. The fix is in the README: the guarantee is per peak level, so cells are safe from about cutoff + 3 dB.
- **Multi-trajectory output names**: see item 5; `-S` is not disambiguated when given once, and `-o` with equal stems can collide (C x2).

**Corroborated by several reviewers (C), not re-run by me**

- **Constant, zero-span or duplicated operating-condition axis** (Rc, C x8, rated high by two reviewers). `sphere_database.cpp:1170` and `:1172` (I re-read them at HEAD: mu and gamma are divided by `max - min` unguarded; only CT is exempted, and only under `fixed_load_factor`). A level-flight-only database would hit it: a database whose gamma, mu or CT is constant normalizes 0/0 to NaN, the triangulation is built on NaN, and every query silently returns one arbitrary sphere. Experiment: a 6-sphere database with gamma = 0 returns 114.000 dB at four different (mu, CT) whose true levels are 100 to 112. A duplicated condition leaves zero-volume simplices: either an abort with "could not locate a simplex" or every query walking 95k steps. Databases come from panam, so malformed ones are plausible. Fix: guard the three normalizations (a zero span maps to 0), reject exact duplicates in `ConditionInterpolator::build` naming both spheres.
- **Grid cells no channel reaches read as a measured 0 dBA / 0 EAA, and unmatched channels are dropped without a message** (C x4). Initialize cells to `{no_energy_floor_db, 0}`, which is bit-identical for every shipped file, and count what was dropped.
- **netCDF variables are read with the file's storage type taken on faith** (C x2): a float32 `.nod` loads as garbage (`Max level 2.8e14`, sphere radius 0) and the CLI exits 0 with an all-NaN footprint. Read through `nc_get_var1_double`/`nc_get_vara_double`.
- **Sphere nose at zero or vertical velocity** (C x4, one rated high). At HEAD this is **partly fixed**: `9fc714a` orients the sphere by the heading below 5 kt when the track has a heading or `--frame_bearing` is set. What remains: `sphere_frame` (`sphere_database.cpp:678`) still returns a zero nose for exactly zero velocity or velocity parallel to the TPP normal, so geodetic tracks with no heading and no `--frame_bearing` look every observer up at the same direction. Narrow now; worth a guard.
- **Plotting after a failed single-trajectory run dereferences an empty `std::optional`** (C x2, `niceops.cpp:2816` passes `*trajectory_holder` with no check). Rc. Needs a plotting build to see; the fix is a one-line guard.
- **Sphere export** (C x2 to x3 each): `interpolate_sphere` adds the load-factor correction to empty (floor) cells, lifting them above the empty threshold so a re-imported sphere reads -117 to -809 dB next to a gated direction (not reachable with shipped data); `write_sphere` drops `speed_reference` and tip speed, so an air-referenced database reloads as ground-referenced with NaN tip speed (latent until panam writes the attribute); `write_sphere` ignores `nc_close`'s status; `--export_sphere` can overwrite the input.
- **Atmosphere and ground options are not range-checked** (see item 2); also `ground/A.r1.4` (negative heights), `ground/A.r1.2` (every non-passive band is refused even outside `--band_limits`).
- **`Delaunay::barycentric` on a hull-boundary query depends on the previous query** (S, no effect with the shipped extension); **the finite enclosing simplex (1000x extent) loses real simplices for point sets thinner than about 2e-4 of their extent** (S, would matter for a near-planar condition set); **`pack_spectra` shifts a 64-bit mask by band >= 64** (C x2, UB for databases with more than 64 bands).
- **`reflected_eigenray` returns a root that is not an eigenray when the receiver is above the source under downward refraction** (S, fuzz: 117 of 912 such cases wrong, ground geometry 19 percent off, 2 to 3 dB in mid bands in the example).
- **Atmosphere profile CSV accepts NaN/inf and drops levels with an unparseable cell silently** (S); **projection has no longitude wrap or distance sanity check** (R, C x2). With a reference at 179.99 degrees east, a point at -179.995 degrees (about 1.6 km east of it) projects to 32,091 km west and 19,478 km north, with no error; a sign-flipped `--origin` does the same. `LocalFrame::to_local` says it throws outside the projection's domain, but a distant point is inside it. Wrap the longitude difference to [-180, 180) and reject positions more than a few hundred kilometers from the reference. Rare in practice (Aleutians, Fiji), cheap to fix.
